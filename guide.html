Hướng Dẫn Sử Dụng

Tổng Quan

Site này là blog tĩnh cho GitHub Pages. Các bài viết được lưu bằng Markdown trong thư mục posts/<folder-slug>/, còn danh sách hiện trên trang chủ được khai báo trong assets/js/posts.js.

Trang Chủ

  • Search: tìm theo tên challenge, tên giải CTF, ngày, tag hoặc summary.
  • CTF filter: chọn một giải để chỉ xem các writeup trong giải đó.
  • Tag filter: lọc theo dạng bài như web, reverse, crypto, pwn.
  • Folder card: mỗi khối là một giải CTF, bên trong là các challenge/writeup của giải đó.

Đọc Writeup

  • Click vào tên challenge để mở trang đọc.
  • Khung Contents bên trái tự động lấy các heading ## và ### trong Markdown.
  • Code block được highlight tự động nếu bạn ghi đúng language, ví dụ ```python, ```bash, ```js.
  • Nút copy trong mỗi code block dùng để lấy payload, command hoặc solve script.

Editor

  • Title: tên challenge/writeup.
  • Date: ngày publish, định dạng YYYY-MM-DD.
  • Tags: danh sách tag cách nhau bằng dấu phẩy, ví dụ web, sqli, auth.
  • Event / CTF: tên giải, ví dụ ImaginaryCTF 2025.
  • Folder slug: tên thư mục không dấu, không space, ví dụ imaginaryctf-2025. Khi bạn nhập Event / CTF, trường này sẽ tự gợi ý nếu bạn chưa sửa thủ công.
  • Split: viết Markdown bên trái và xem preview bên phải.
  • Write: chỉ hiện khung viết.
  • Preview: chỉ hiện bản render.
  • Import .md: nạp một file Markdown có sẵn vào editor.
  • Export .md: tải file Markdown kèm front matter.
  • Export HTML: tải bản HTML đã render, hữu ích khi cần nộp riêng.

Import / Export Là Gì?

  • Import .md: mở một file Markdown từ máy của bạn vào editor để sửa tiếp. Nút này không đăng bài lên web.
  • Export .md: tải writeup thành file Markdown. Đây là file chính bạn đặt vào posts/<folder-slug>/ để publish lên blog.
  • Export HTML: tải một bản HTML đã render sẵn. Bản này hữu ích nếu bạn muốn gửi riêng cho ai đó, nhưng bình thường không cần dùng khi deploy GitHub Pages.

Đăng Bài Mới

  1. Mở editor.html và viết writeup.
  2. Điền Event / CTF và Folder slug.
  3. Kiểm tra dòng suggested ở footer editor để biết đường dẫn nên đặt file.
  4. Bấm Export .md.
  5. Tạo thư mục theo gợi ý, ví dụ posts/imaginaryctf-2025/.
  6. Đưa file Markdown vừa export vào thư mục đó.
  7. Trong editor, copy phần window.CTF_POSTS entry và dán vào window.CTF_POSTS trong assets/js/posts.js.
{
  slug: "challenge-name",
  title: "Challenge Name",
  date: "2026-05-17",
  event: "imaginaryctf-2025",
  tags: ["web", "auth"],
  summary: "Tóm tắt ngắn hiện trên trang chủ.",
  file: "posts/imaginaryctf-2025/2026-05-17-challenge-name.md"
}

Nếu đây là giải CTF mới, thêm metadata vào window.CTF_EVENTS:

{
  slug: "imaginaryctf-2025",
  name: "ImaginaryCTF 2025",
  date: "2025",
  summary: "Writeups for ImaginaryCTF 2025."
}

Có Cần Sửa HTML Không?

Không cần sửa các file HTML để thêm bài hoặc thêm giải. Các file HTML chỉ là khung giao diện. Nội dung blog nằm ở hai chỗ:

  • File writeup Markdown trong posts/<folder-slug>/.
  • Metadata trong assets/js/posts.js.

Vì GitHub Pages là static hosting, trình duyệt không thể tự tạo file mới trong repo hoặc tự commit lên GitHub. Bạn có thể viết, preview, import và export trên giao diện web; bước publish vẫn cần đưa file Markdown và metadata vào repo rồi push lên GitHub.

Owner Mode

Owner controls are visible automatically on localhost and 127.0.0.1. On the deployed site, public visitors only see the reading interface.

If you want to enable owner controls in your own deployed browser, open the site once with ?owner=1. To hide them again, open it with ?owner=0.

Read-only Sharing

Visitors can read the public blog, but they cannot change your GitHub repository from the website. The public navigation only links to posts and this guide. The editor is for the site owner workflow.

If you want a strict read-only deploy, do not publish editor.html and assets/js/editor.js to the GitHub Pages branch. Keep those files locally for writing, then publish only the static reader files.

Deploy GitHub Pages

  1. Đẩy toàn bộ source lên repository GitHub.
  2. Vào Settings của repo.
  3. Chọn Pages.
  4. Source: Deploy from a branch.
  5. Branch: chọn branch chính, folder: /root.
  6. Chờ GitHub build xong, site sẽ có dạng https://username.github.io/ nếu repo tên là username.github.io.
  7. Nếu repo có tên khác, link thường sẽ là https://username.github.io/repository-name/.
