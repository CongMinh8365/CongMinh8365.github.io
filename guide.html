Usage Guide

Overview

This is a static GitHub Pages blog. Writeups are Markdown files under posts/<event-slug>/. The homepage list is controlled by assets/js/posts.js.

Events

Event / CTF is the large folder for a competition or platform. The editor automatically turns the event name into a folder slug.

UMass CTF 2026 -> posts/umass-ctf-2026/
TAMUctf 2026   -> posts/tamuctf-2026/
Hack The Box   -> posts/hack-the-box/

You no longer need to type a separate folder slug.

Files and Images

Use Attach files for challenge files, solve scripts, archives, APKs, binaries, and other downloads. Use Insert images for screenshots.

The editor inserts Markdown links. If you use Upload local in Chrome, Edge, or Brave, the selected assets from the current editor session are also copied into these folders:

posts/<event-slug>/files/
posts/<event-slug>/images/

Markdown examples:

[challenge binary](files/batcave_license_checker)
[solve script](files/solve.py)
![IDA screenshot](images/ida-main.png)

Insert images shows a local preview immediately from the selected image. The final public site still needs the image file to exist under posts/<event-slug>/images/.

If you close or reload the editor before uploading, re-attach the asset files or copy them manually. Browsers do not keep real file objects inside localStorage.

You can also paste images into the editor. If the clipboard contains an image URL, the editor inserts that URL. If it contains raw image data, the editor inserts a data URL. Data URLs work, but they make the Markdown file large, so repository images are cleaner for final posts.

Editor

  • Title: writeup title.
  • Date: publish date.
  • Tags: comma-separated tags such as reverse, crypto, web.
  • Event / CTF: competition folder name.
  • Split: write on the left, preview on the right.
  • Write: editor only.
  • Preview: rendered Markdown only.
  • Import .md: open an existing Markdown file for editing.
  • Export .md: download the final Markdown file.
  • Export HTML: download a rendered HTML copy, usually not needed for GitHub Pages.
  • Upload local: write the Markdown file, copied current-session assets, and assets/js/posts.js into your local project folder.
  • New draft: clear the current autosaved draft and start from the template.
  • Delete post: remove a post entry from assets/js/posts.js and delete its Markdown file locally.

Code Highlighting

Use fenced code blocks with a language name. Highlight.js handles common languages such as Python, JavaScript, Bash, C, C++, Java, Go, Rust, PHP, Ruby, JSON, YAML, HTML, CSS, SQL, and HTTP.

```python
print("solve")
```

```c
int main(void) {
  return 0;
}
```

Autosave

The editor autosaves your draft to browser localStorage after edits. You can close the browser or shut down the machine and continue later from the same browser profile.

Autosave is only a draft cache. Use Upload local or export the Markdown file before publishing.

Publish

  1. Write the post in editor.html.
  2. Fill Title, Date, Tags, and Event / CTF.
  3. Add files and images if needed.
  4. Set Homepage summary if the generated summary is not what you want. This text is only shown on the homepage card.
  5. Click Upload local.
  6. Choose the project root folder, for example D:\Cong Minh\Blog CTF.
  7. The editor writes the Markdown file, copies assets selected in this session, and updates assets/js/posts.js.
  8. Run git add ., git commit, and git push.

If Upload local is not available in your browser, use Export .md, copy assets manually, then copy the generated entries into assets/js/posts.js.

Owner Mode

Owner controls are visible automatically on localhost and 127.0.0.1. Public visitors do not see Editor, Guide, or New writeup.

Enable owner mode in your deployed browser with ?owner=1. Disable it with ?owner=0.

Deploy

After local changes, push them to GitHub:

git add .
git commit -m "Update blog"
git push

GitHub Pages redeploys automatically after the push.
